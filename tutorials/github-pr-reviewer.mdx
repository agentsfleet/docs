## What you will build

Create a fleet that reviews pull requests in one GitHub repository. Its review appears in the fleet's chat.

## Before you begin

[Install the command-line interface (CLI)](/cli/install) and sign in. Select a workspace with an available model and balance.

Use **Connected apps** to connect GitHub to that workspace. Give the App access to the repository you want to review. [Connect a provider](/fleets/connectors) covers the installation.

## Steps

1. Start the fleet. Replace `OWNER/REPOSITORY` with the connected repository.

   ```bash
   agentsfleet fleet create --name pr-reviewer "Add a GitHub pull_request trigger for OWNER/REPOSITORY. When it wakes you, review the changes and report correctness and test gaps in this chat. Ask for read access to this repository when you need it."
   ```

   ```text
   ✓ Started fleet pr-reviewer (<FLEET_ID>). First turn <TURN_ID>: <varies>.
   Talk to it with: agentsfleet fleet steer <FLEET_ID>
   ```

2. Open the fleet in the dashboard and check that **Wakes on** lists the repository. If an access card appears, check the repository and read scope before approving it.
3. Open a pull request in GitHub. Review the fleet's reply after its turn completes.

## Verify it works

Use the identifier from the create response to find the fleet's turns.

```bash
agentsfleet fleet turns <FLEET_ID> --actor github-app
```

```text
<varies>
```

The turn should identify the repository event. Check the reply for the review. If the fleet cannot read the changes, check the GitHub connection and the fleet's approved repository scope.

## What you learned

You started a fleet from the terminal, subscribed it to a repository, and checked its review in chat.
