## What it is

A runner is a Linux host that takes work from agentsfleet. It starts the model and runs local tools in a sandbox. The daemon assigns work and keeps the final result.

## Why it exists

Runners keep fleet tools separate from the service that stores accounts, permissions, and messages. You can add hosts for capacity and limit what each host can do.

## How it behaves

### Enrolling a host

Use an operator credential with `runner:register`. Choose the host identifier and prepare its assigned policy JSON file. The command writes the token to a new private file.

```bash
agentsfleet platform runners register --host-id <HOST_ID> --policy <POLICY_FILE> --token-out <TOKEN_FILE>
```

```text
<varies>
```

`<HOST_ID>` names the machine. `<POLICY_FILE>` is the local policy file, and `<TOKEN_FILE>` is the new path for the runner token. The server shows the token only at creation or rotation.

[Install the runner](/runners/install) on that host. An account with `runner:tenant` can use `agentsfleet runners register` for its own work. A tenant-controlled runner handles work from its account using that account's model key.

### The runner connection

The runner opens one authenticated connection to its private listener. It prefers HTTP/3 and can use HTTP/2 if the first connection fails in an eligible way.

| Required setting | What it supplies |
|---|---|
| `AGENTSFLEET_API_URL` | The control-plane address for remaining HTTP requests |
| `AGENTSFLEET_RUNNER_STREAM_URL` | The private secure HTTP (HTTPS) listener origin, without a path or credentials |
| `AGENTSFLEET_RUNNER_TOKEN` | The token issued for this host |

Your operator supplies the route to the listener. Allow its port over User Datagram Protocol (UDP) and Transmission Control Protocol (TCP). The default port is 4443.

Both transports use Transport Layer Security (TLS) 1.3 with `X25519MLKEM768` key exchange. The certificate must match the listener's hostname. For a private issuer, set `AGENTSFLEET_RUNNER_STREAM_TLS_CA_CERT_FILE` to its public certificate bundle.

### Results during an outage

The runner retries a result it still holds while it reconnects. Stopping the process can lose results the daemon has yet to accept. The daemon keeps results it already accepted.

### What the runner sends to a collector

Set `OTEL_EXPORTER_OTLP_ENDPOINT` to send traces and metrics to an OpenTelemetry collector. The runner sends timings and identifiers for runs and tool calls. Prompts, replies, tool outputs, and credentials stay out of these records.

The runner rejects credential headers and authentication in the collector URL. Configure authentication on the collector if it forwards data.

### The policy you assign

Set the sandbox tier, network policy, worker count, and durable task setting in the assigned policy. Use `agentsfleet platform runners update <RUNNER_ID> --policy <POLICY_FILE>` to replace it.

Each heartbeat reports what the host can enforce. If the host cannot meet its assigned policy, the daemon marks it degraded and withholds new work. The next heartbeat checks the new policy.

Change labels with `agentsfleet platform runners update <RUNNER_ID> --labels <LABELS>`. Labels help choose a runner for a fleet. They grant no permissions.

### Tools inside a sandbox

A Linux sandbox uses bubblewrap and Landlock. Local tools work inside the fleet's workspace. The host's network policy controls where sandbox processes can connect.

The `git` tool can read and change its local checkout. Remote commands such as `git push`, `git fetch`, and `git clone` are refused.

### The states a runner shows

Get `<RUNNER_ID>` from `agentsfleet platform runners list`. Inspect its state before changing or stopping it.

```bash
agentsfleet platform runners show <RUNNER_ID>
```

```text
<varies>
```

| Administrative state | Meaning |
|---|---|
| `active` | The runner can take work. |
| `cordoned` | Operator action stopped work and runner requests. |
| `draining` | The operator requested a drain. |
| `drained` | The runner has finished draining. |
| `revoked` | The runner token is blocked. |

Liveness shows what the host is doing. `registered` has yet to send a heartbeat. `online`, `busy`, and `offline` mean connected and idle, running work, or missing heartbeats.

### When a runner stops taking work

Use `agentsfleet platform runners cordon`, `drain`, or `revoke` with the runner identifier. Let the runner report active work before imposing a cordon or drain. Those actions can block renewals and completion reports.

If the host disappears, its unfinished work becomes eligible after the lease expires. See [Recovery after a runner fails](/runners/recovery).

### Lease history

A lease records which runner took a run. Use `agentsfleet platform runners runs <RUNNER_ID>` to read its runs. Use `agentsfleet platform runners history <RUNNER_ID>` to inspect events such as registration, cordon, and return.

The API exposes the same lists at `GET /v1/admin/runners/{runner_id}/runs` and `GET /v1/admin/runners/{runner_id}/history`.

## Limits

A host must support the isolation its policy requires. Use `agentsfleet-runner probe` before starting the service.

Upgrade the runner and daemon together so they use the same protocol. A tenant runner handles only its account's work and cannot use the platform model credential.
