# Command reference

## Synopsis

The command-line interface (CLI) manages workspaces, fleets, access, secrets, and memory.

```text
agentsfleet [GLOBAL_OPTIONS] <COMMAND>
```

`<COMMAND>` comes from the tables below. Run any command with `--help` to see its accepted values.

Identifier placeholders come from the matching create or list command. You choose name, path, provider, message, and query values.

## Example with output

```bash
agentsfleet --help
```

```text
DESCRIPTION
  agentsfleet cli

USAGE
  agentsfleet <subcommand> [flags]

FLAGS
  --api <url>    API base URL
  --json         Machine-readable JSON output
<varies>
SUBCOMMANDS
  login        Authenticate via browser
<varies>
  chat         Create, resume, and review a private workspace chat
  fleet        Fleet management subcommands
<varies>
```

## Options

### Global options

`<API_URL>` is the API base URL for your deployment.

| Option | Effect | Default | Unit or range |
|---|---|---|---|
| `-v`, `--version` | Prints the client version and exits. | `false` | Boolean |
| `--api <API_URL>` | Sends requests to this API URL. | `https://api.agentsfleet.net` | URL beginning with `http://` or `https://` |
| `--json` | Prints JSON when the command supports it. | `false` | Boolean |
| `-h`, `--help` | Prints help and exits. | `false` | Boolean |

### Login options

Write these after `login`. Only `agentsfleet login` reads them.

| Option | Effect | Default | Unit or range |
|---|---|---|---|
| `--no-open` | Prints the login URL instead of opening a browser. | `false` | Boolean |
| `--no-input` | Returns an error instead of asking a question. | `false` | Boolean |
| `--force` | Signs in again even when this computer already holds a credential. | `false` | Boolean |
| `--token-name <LABEL>` | Labels this sign-in on the approval page and in `agentsfleet whoami`. | The platform family name | Text |

### Account and diagnosis

| Command | Effect |
|---|---|
| `agentsfleet login` | Signs in through a browser and saves a durable credential for this computer. |
| `agentsfleet logout` | Revokes this computer's credential and any unfinished sign-in, then clears local credentials. Browser sessions stay signed in. |
| `agentsfleet whoami` | Shows who this terminal is signed in as, the credential's source (`environment` or `file`), and the server it talks to. |
| `agentsfleet doctor` | Checks client settings, authentication, and API access. |

### Workspaces and access

| Command | Effect |
|---|---|
| `agentsfleet workspace create <NAME>` | Creates a workspace and selects it. The name is required. |
| `agentsfleet workspace list` | Lists workspaces. |
| `agentsfleet workspace use <WORKSPACE_ID>` | Selects the active workspace on this computer. |
| `agentsfleet workspace show [WORKSPACE_ID]` | Shows one workspace. |
| `agentsfleet workspace secrets` | Prints the secret command and dashboard path. |
| `agentsfleet workspace delete <WORKSPACE_ID>` | Removes one workspace from local client state. Remote data remains. |
| `agentsfleet api-key create --name <NAME>` | Creates a tenant API key. `--name` is required, and the raw key appears once. |
| `agentsfleet api-key list` | Lists tenant API keys. |
| `agentsfleet api-key revoke <API_KEY_ID>` | Revokes a tenant API key. Calls using that key fail. |
| `agentsfleet api-key delete <API_KEY_ID>` | Deletes metadata for a revoked tenant API key. |
| `agentsfleet connector list` | Lists connector setup and connection state. |
| `agentsfleet connector show <PROVIDER>` | Shows one connector. |
| `agentsfleet grant list --fleet <FLEET_ID>` | Lists integration grants for one fleet. |
| `agentsfleet grant delete --fleet <FLEET_ID> <GRANT_ID>` | Revokes one grant. Later access through that grant fails. |

### Chat

`agentsfleet chat` creates, resumes, and reviews a private draft. It is the only way to create a fleet or a Library entry from the terminal. Only the person who starts a draft can read it.

| Command | Effect |
|---|---|
| `agentsfleet chat --model <MODEL_REF>` | Starts a blank draft and opens an interactive chat. |
| `agentsfleet chat <DRAFT_ID>` | Resumes a draft and prints its earlier messages. |
| `agentsfleet chat --definition <PATH> --model <MODEL_REF>` | Starts a draft from a Definition JSON file, with no chat message. |
| `agentsfleet chat --library <LIBRARY_ID> --revision <REVISION_ID> --model <MODEL_REF>` | Starts a draft from one Library revision, with no chat message. |
| `agentsfleet chat --fleet <FLEET_ID> --setup-revision <SETUP_REVISION> --model <MODEL_REF>` | Starts a draft that improves an existing fleet, with no chat message. |

`<MODEL_REF>` is the `ref` of an authoring model from `GET /v1/workspaces/{workspace_id}/models?purpose=authoring`. `<SETUP_REVISION>` is the fleet's `setup_revision` field from `agentsfleet --json fleet show <FLEET_ID>`.

In an interactive chat, ordinary text is a message. These actions start with `/`:

| Slash command | Effect |
|---|---|
| `/review [INSTANCE_NAME]` | Prints the full setup, its required access, its readiness checks, and its review digest. The name selects the fleet name. |
| `/save` | Saves the reviewed setup as a new fleet. |
| `/run <MESSAGE>` | Saves the reviewed setup and sends the fleet `<MESSAGE>` once. |
| `/publish <LABEL>` | Publishes the reviewed setup as a Library entry. |
| `/apply` | Applies the reviewed improvement to its source fleet. |
| `/model <MODEL_REF>` | Changes the authoring model for later messages. |
| `/stop` | Cancels every accepted message in the draft that has not finished. Ctrl+C stops the reply you are following. |
| `/retry` | Repeats the last action whose outcome was unknown. |
| `/delete` | Deletes the draft and its private messages. |
| `/quit` | Leaves the chat. The draft stays for `agentsfleet chat <DRAFT_ID>`. |

Save, publish, and apply each use only the setup you last reviewed. A message after a review needs a new review first.

Outside a terminal, add `--no-input` and name every action as a flag. This pair reviews a Definition, then saves it with the digest the review printed:

```bash
agentsfleet chat --definition <PATH> --model <MODEL_REF> --no-input --review --name <NAME>
```

```text
✓ Draft <DRAFT_ID> created
Instance: <NAME>
<varies>
Review digest: <DIGEST>
```

```bash
agentsfleet chat <DRAFT_ID> --no-input --save --name <NAME> --review-digest <DIGEST>
```

```text
<varies>
✓ Fleet <NAME>: active
```

| Option | Effect | Default | Unit or range |
|---|---|---|---|
| `--model <MODEL_REF>` | Selects the authoring model for a new draft. Required unless you resume a draft. | None | Model reference |
| `--message <TEXT>` | Sends one chat message and follows its reply. | None | 1 to 32,768 bytes |
| `--definition <PATH>` | Starts from a Definition JSON file. | None | Readable file, at most 128 KiB |
| `--library <LIBRARY_ID>` | Starts from a Library entry. Needs `--revision`. | None | Library identifier |
| `--revision <REVISION_ID>` | Selects the exact Library revision. | None | Revision identifier |
| `--fleet <FLEET_ID>` | Starts an improvement of an existing fleet. Needs `--setup-revision`. | None | Fleet identifier |
| `--setup-revision <SETUP_REVISION>` | Selects the fleet setup revision to improve. | None | Positive whole number |
| `--no-input` | Runs only the actions you name, with no prompt. | `false` | Boolean |
| `--review` | Prints the full setup, access, readiness, and review digest. | `false` | Boolean |
| `--name <NAME>` | Selects the fleet name before the review. | The draft's current fleet name | Lowercase letters, digits, and hyphens |
| `--review-digest <DIGEST>` | The digest of the review you inspected. Required with `--save`, `--apply`, and `--publish`. | None | Digest text |
| `--save` | Saves the reviewed setup as a new fleet. | `false` | Boolean |
| `--run-now <TEXT>` | With `--save`, sends the new fleet this message once. | None | 1 to 32,768 bytes |
| `--apply` | Applies the reviewed improvement to its source fleet. | `false` | Boolean |
| `--publish <LABEL>` | Publishes the reviewed setup as a Library entry with this label. | None | 1 to 100 characters |
| `--publish-to <LIBRARY_ID>` | With `--publish`, adds a revision to this owned entry instead. | None | Library identifier |
| `--library-etag <ETAG>` | The entry tag you inspected. Required with `--publish-to`. | None | Entity tag |
| `--stop` | Cancels every accepted message in the draft that has not finished. | `false` | Boolean |
| `--operation-id <ID>` | Retries an action whose outcome was unknown, under its first identity. | None | Identifier the client printed |
| `--candidate-id <ID>` | With `--operation-id`, names the setup the retried Save, Apply, or publish used. | None | Identifier the client printed |
| `--setup-etag <ETAG>` | With `--operation-id` and `--apply`, names the fleet setup tag you inspected. | None | Identifier the client printed |

One invocation takes one source and at most one of `--save`, `--apply`, and `--publish`. A digest that does not match the current review is refused with exit code `4`.

A Save that leaves the fleet `installing` prints each waiting check and exits with code `1`. A Save, Apply, or publish whose reply was lost prints the `--operation-id` and `--candidate-id` values to retry with.

### Fleets

| Command | Effect |
|---|---|
| `agentsfleet library` | Lists the workspace gallery: every entry this workspace can use, platform and workspace alike. |
| `agentsfleet library list` | Lists only the entries this workspace owns. |
| `agentsfleet library delete <LIBRARY_ID>` | Removes one entry this workspace owns, with its revision history. Fleets saved from it keep running. |
| `agentsfleet fleet show <FLEET_ID>` | Shows one fleet. |
| `agentsfleet list` | Lists fleets in the active workspace. `--starting-after <CURSOR>` fetches the next page. |
| `agentsfleet status` | Shows every fleet in the active workspace, including how many approvals each one is waiting on. It takes no identifier — use `agentsfleet fleet show <FLEET_ID>` for one fleet. |
| `agentsfleet stop <FLEET_ID>` | Stops new work. You can resume the fleet. |
| `agentsfleet resume <FLEET_ID>` | Resumes a stopped or paused fleet. On an `installing` fleet, it checks setup again and activates the fleet when every check passes. |
| `agentsfleet kill <FLEET_ID>` | Marks a fleet as killed. This cannot be undone. On an `installing` fleet, it cancels setup and returns the draft to editing. |
| `agentsfleet delete <FLEET_ID>` | Deletes a killed fleet and its stored data. This cannot be undone. |
| `agentsfleet logs [FLEET_ID]` | Shows recent activity. |
| `agentsfleet events <FLEET_ID>` | Lists historical events with filters. |
| `agentsfleet steer <FLEET_ID> [MESSAGE]` | Sends a message and streams the response. |

`agentsfleet delete` has no dry-run option. Run `agentsfleet kill` first, then check the fleet identifier before deletion.

`agentsfleet library` and `agentsfleet library list` answer different questions. The first lists everything this workspace can use, platform entries included. The second lists only what this workspace owns, which is the set `agentsfleet library delete` can act on.

`agentsfleet library delete` removes an entry permanently. Removing a platform entry, another workspace's entry, or one already gone answers `UZ-AUTHOR-001` and exits with code `3`.

Fleets and Library entries come only from reviewed chat drafts. The file, GitHub, and template import commands, `agentsfleet install`, and `agentsfleet fleet update` were removed; `agentsfleet chat` replaces them.

### Approvals

| Command | Effect |
|---|---|
| `agentsfleet approvals list` | Lists the gates waiting for a decision in the active workspace. |
| `agentsfleet approvals list --fleet <FLEET_ID>` | Lists the waiting gates for one fleet. |
| `agentsfleet approvals show <GATE_ID>` | Shows one gate, including the reach an approval grants. |
| `agentsfleet approvals approve <GATE_ID>` | Approves the gate. The parked run continues. |
| `agentsfleet approvals deny <GATE_ID>` | Denies the gate. The parked run ends without the access it asked for. |

A fleet whose Definition declares `repository_access: write` opens a gate on every run. The run parks until a person decides that gate, so an unresolved gate stops `agentsfleet steer` from finishing.

A decision is final. The next run opens its own gate, and the previous decision does not carry over.

### Schedules

Every subcommand takes the fleet identifier. The four that act on one schedule
take its identifier after it.

| Command | Effect |
|---|---|
| `agentsfleet schedule create <FLEET_ID> --cron <EXPRESSION> --message <TEXT>` | Creates a schedule that wakes a fleet on a cron expression. |
| `agentsfleet schedule list <FLEET_ID>` | Lists the schedules a fleet holds. |
| `agentsfleet schedule update <FLEET_ID> <SCHEDULE_ID>` | Changes an existing schedule. |
| `agentsfleet schedule delete <FLEET_ID> <SCHEDULE_ID>` | Deletes one schedule. |
| `agentsfleet schedule show <FLEET_ID> <SCHEDULE_ID>` | Shows one schedule and its state at the upstream scheduler. |
| `agentsfleet schedule sync <FLEET_ID> <SCHEDULE_ID>` | Re-sends the schedule to the upstream scheduler. |

Run `agentsfleet schedule sync <FLEET_ID> <SCHEDULE_ID>` after `UZ-SCHED-004`, the code the server returns when the upstream scheduler did not confirm a change.

Each option is accepted by the subcommands named beside it.

| Option | Accepted by | Effect | Default | Unit or range |
|---|---|---|---|---|
| `--cron <EXPRESSION>` | `create`, `update` | Sets when the schedule fires. | Unset | Five-field cron expression |
| `--message <TEXT>` | `create`, `update` | Sets the message the fleet receives on each fire. | Unset | Text |
| `--timezone <TIMEZONE>` | `create`, `update` | Reads the cron expression in this zone. | `UTC` on `create` | Supported region name |
| `--status <STATE>` | `update` | Sets whether the schedule fires. | Unset | `active` or `paused` |
| `--workspace <WORKSPACE_ID>` | all six | Targets a workspace other than the active one. | Active workspace | Workspace identifier |

A fleet holds at most 32 schedules.

### Secrets and memory

| Command | Effect |
|---|---|
| `agentsfleet secret create <NAME>` | Stores a JSON object in the workspace vault under a name that is free. A name already in use is reported as skipped, and nothing is written. |
| `agentsfleet secret create <NAME> --provider <ID> --api-key <KEY> --model <MODEL>` | Stores a model-provider credential. `--provider` and `--model` are both checked against the model catalogue your server serves — run `agentsfleet models` to list it. `--provider openai-compatible` adds a required `https` `--base-url`, makes `--api-key` optional, and accepts any `--model`. |
| `agentsfleet secret update <NAME>` | Replaces a stored secret without releasing its name. It accepts the same data and provider options as `agentsfleet secret create`. |
| `agentsfleet secret show <NAME>` | Confirms that a secret exists without showing its value. |
| `agentsfleet secret list` | Lists secret names, kinds, and creation times as a table. `--json` returns the same fields it always has. |
| `agentsfleet secret delete <NAME>` | Deletes a secret. Fleets using the secret fail on their next use. |
| `agentsfleet memory list --fleet <FLEET_ID>` | Lists memory entries newest first. |
| `agentsfleet memory search <QUERY> --fleet <FLEET_ID>` | Searches memory keys and content. |

`agentsfleet secret delete` has no dry-run option. The deleted secret value cannot be recovered.

### Model catalogue

| Command | Effect |
|---|---|
| `agentsfleet models` | Lists every model the server prices: provider, model id, context window, and per-million-token input and output rates. |
| `agentsfleet models --provider <ID>` | Lists one provider's models. |

The dashboard's model picker reads the same catalogue, so both surfaces offer
the same providers. Rates apply under platform-managed posture; a self-managed
credential is billed by your own provider account, and its rows show a dash.

An empty catalogue means an administrator has not primed this server yet. While
it is empty, `--provider` accepts any value and the server validates the
credential.

### Tenant settings

| Command | Effect |
|---|---|
| `agentsfleet tenant provider show` | Shows the active model provider. |
| `agentsfleet tenant provider create --secret <NAME>` | Selects a self-managed provider secret. |
| `agentsfleet tenant provider delete` | Returns the tenant to the platform provider. |
| `agentsfleet billing show` | Shows the tenant balance and recent charges. |

## Errors

| Exit code | Meaning |
|---|---|
| `0` | The command succeeded. |
| `1` | Authentication, session, or unexpected failure. |
| `2` | Network failure or rate limit. |
| `3` | The API returned a server failure. |
| `4` | The invocation was rejected: a missing argument, a missing or unrecognized flag, a value that failed validation, or an unknown command. |
| `5` | Local configuration is missing or invalid. |
| `130` | You interrupted the command. |

A rejected invocation is answered before any request is sent. The form is always the same: what is wrong, then the command that puts it right. What is wrong may be an absent argument, a value that failed validation, or an unrecognized command.

```
$ agentsfleet events
✕ error: missing required argument 'fleet_id'
  Suggestion: usage: agentsfleet events [options] <fleet_id>
```

Under `--json` the same rejection is a parseable envelope on standard error, carrying a stable `code` you can switch on:

```json
{
  "error": {
    "code": "MISSING_ARGUMENT",
    "message": "missing required argument 'fleet_id'"
  }
}
```

The codes are `MISSING_ARGUMENT`, `MISSING_OPTION_VALUE`, `MISSING_REQUIRED_OPTION`, `UNKNOWN_COMMAND`, `UNKNOWN_OPTION`, `INVALID_ARGUMENT`, and `EXCESS_ARGUMENTS`.

API failures include a stable error code and request identifier when the server supplies them. Use both values when reporting a problem.

A server failure is reported with the message the server wrote for a reader, not with its internal detail text. A Save refused after a setup change reads `This setup changed. Review it before saving.` in place of the server's detail text.

The [error registry](/api-reference/error-codes) lists the message each code carries.
