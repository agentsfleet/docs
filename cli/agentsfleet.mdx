## Synopsis

The command-line interface (CLI) manages workspaces, fleets, access, secrets, and memory.

```text
agentsfleet [GLOBAL_OPTIONS] <COMMAND>
```

`<COMMAND>` comes from the tables below. Run any command with `--help` to see its accepted values.

Every fleet command sits under `agentsfleet fleet`. Help lists `agentsfleet platform` commands only when your account holds a scope that can use them. A hidden command still runs, and the server still decides.

Identifier placeholders come from the matching create or list command. You choose name, path, provider, message, and query values.

## Platform administration

Platform administration is available in the terminal. The dashboard has no Platform settings page.

The server checks the signed-in credential’s scopes on every request. A command appearing in help does not grant permission to run it.

| Command group | Purpose | Required scopes |
|---|---|---|
| `agentsfleet platform models default` | Inspect or set the platform default provider and model. Stored keys stay hidden. | `platform-key:read` for list; `platform-key:admin` for set/delete |
| `agentsfleet platform models` | List, inspect and maintain the priced model catalogue. | `model:read` for reads; `model:admin` for writes |
| `agentsfleet platform runners` | Inspect hosts, enroll them, update policy and manage their lifecycle. | `runner:read`, `runner:register` or `runner:write`, according to the operation |

Choose a catalogued model backed by an existing provider credential in the named workspace:

```bash
agentsfleet platform models default use --provider <PROVIDER_ID> --workspace <WORKSPACE_ID> --model <MODEL_ID>
```

```text
Platform default selected
Provider  <PROVIDER_ID>
Model     <MODEL_ID>
Active    Yes
```

The command confirms the stored default metadata without revealing the key.

Use `agentsfleet platform models default list` to check the result. Save the provider's key in the workspace before selecting it.

## Options

### Global options

`<API_URL>` is the API base URL for your deployment.

| Option | Effect | Default | Unit or range |
|---|---|---|---|
| `-v`, `--version` | Prints the client version and exits. | `false` | Boolean |
| `--api <API_URL>` | Sends requests to this API URL. | `https://api.agentsfleet.net` | URL beginning with `http://` or `https://` |
| `--json` | Prints JSON when the command supports it. | `false` | Boolean |
| `-h`, `--help` | Prints help and exits. | `false` | Boolean |
| `--completions <SHELL>` | Prints a completion script for `bash`, `zsh`, `fish` or `powershell` and exits. Write it to a file and regenerate it after you sign in, change server, or gain or lose a scope. | Not set | `bash`, `zsh`, `fish`, `powershell`, `sh`, `pwsh` |

### Login options

Write these after `login`. Only `agentsfleet login` reads them.

| Option | Effect | Default | Unit or range |
|---|---|---|---|
| `--no-open` | Uses manual code entry and prints a URL you can open on another device. | `false` | Boolean |
| `--no-input` | Returns an error instead of asking a question. | `false` | Boolean |
| `--force` | Signs in again even when this computer already holds a credential. | `false` | Boolean |
| `--token-name <LABEL>` | Sets a label on this sign-in request. | The platform family name | 1 to 64 characters from space through tilde |

#### Browser on this computer

1. Start sign-in from an interactive terminal on the same computer as your browser.

   ```bash
   agentsfleet login
   ```

   ```text
   Connect your terminal
   Open this link on this computer:
   login_url: <varies>
   Check code: <varies>
   Waiting for authorization… (Esc to cancel)
   browser: opened
   <varies>
   Finalizing sign-in…
   ✓ signed in as <varies> — <varies>
   ```

2. Compare the check code in your browser with the code in your terminal.
3. Choose **Authorize** only if you started the sign-in and both codes match.

After approval, the client saves this computer's credential and checks your identity. The terminal then shows your name and account.

The browser shows **Unleash your agents.** after sign-in succeeds. You can close that tab and return to your terminal.

Choose **Deny** if you did not start the sign-in or the codes differ.

Press **Esc** or **Ctrl+C** while waiting to cancel. The waiting request expires after five minutes.

Once **Finalizing sign-in…** appears, cancellation is disabled until sign-in finishes. Keep the terminal open until it reports the result.

If the browser does not open, open the printed `login_url` on this computer.
If the browser cannot reach your terminal, cancel while waiting and restart with `--no-open`.
Start a new sign-in if the request expires.

#### Browser on another device

Use manual code entry for a remote terminal, such as a Secure Shell (SSH) session, or a browser on another device.

1. Start manual sign-in in your interactive terminal.

   ```bash
   agentsfleet login --no-open
   ```

   ```text
   Login session
   session_id: <varies>
   login_url: <varies>
   browser: not opened (open URL manually)
   Enter the 6-digit verification code shown in your browser: <varies>
   ```

2. Open the printed `login_url` in your browser.
3. Choose **Authorize** only if you started this sign-in.
4. Enter the browser's six-digit verification code in the terminal that started sign-in.

The terminal reports **signed in as** with your name and account after sign-in succeeds.
After the terminal verifies your code, the browser replaces the code with **Unleash your agents.**
Manual sign-in requires terminal input, so omit `--no-input`.

### Account and diagnosis

| Command | Effect |
|---|---|
| `agentsfleet login` | Opens same-computer browser authorization and saves a credential after approval. |
| `agentsfleet logout` | Revokes this computer's credential and any unfinished sign-in, then clears local credentials. Browser sessions stay signed in. |
| `agentsfleet whoami` | Shows who this terminal is signed in as, the credential's source (`environment` or `file`), and the server it talks to. |
| `agentsfleet doctor` | Checks client settings, authentication, and API access. |

### Terminal pet

Run Orbit, a local paddle game, in an interactive terminal.

```bash
agentsfleet pet
```

```text
Space serve  S sound off
```

Press **Space** to serve. Move the paddle with the arrow keys or **A** and **D**. Press **R** to restart or **Q** to quit.

You get three lives. Collect stars for 50 bonus points. Each return in a rally earns more points, and the ball speeds up as you return it.

The paddle can return the ball at either edge. A missed ball falls past the paddle, costs a life, and returns to the center.

Restarting keeps your best score for the current session. Press **S** to toggle the sound effects, which start off. Orbit uses the terminal bell if a sound file cannot play.

The court needs at least 35 columns and 14 rows. Resizing the terminal ends the game. Run `agentsfleet pet` again to start over.

The game makes no API requests and requires no sign-in.

The request loader shows a bouncing ball. Set `AGENTSFLEET_REDUCED_MOTION=1` for a static request status.

```bash
agentsfleet pet --json
```

```text
{
  "name": "Orbit"
}
```

Piped output returns the same JSON object.

### Workspaces and access

| Command | Effect |
|---|---|
| `agentsfleet workspace create <NAME>` | Creates a workspace and selects it. The name is required. |
| `agentsfleet workspace list` | Lists workspaces. |
| `agentsfleet workspace use <WORKSPACE_ID>` | Selects the active workspace on this computer. |
| `agentsfleet workspace show [WORKSPACE_ID]` | Shows one workspace. |
| `agentsfleet workspace delete <WORKSPACE_ID>` | Removes one workspace from local client state. Remote data remains. |
| `agentsfleet api-keys create --name <NAME>` | Creates a tenant API key. `--name` is required, and the raw key appears once. |
| `agentsfleet api-keys list` | Lists tenant API keys. |
| `agentsfleet api-keys revoke <API_KEY_ID>` | Revokes a tenant API key. Calls using that key fail. |
| `agentsfleet api-keys delete <API_KEY_ID>` | Deletes metadata for a revoked tenant API key. |
| `agentsfleet connections list` | Lists connector setup and connection state. |
| `agentsfleet connections show <PROVIDER>` | Shows one connector. |

### Chat

Start a fleet by sending its first message.

```bash
agentsfleet fleet create "Check the nightly health report" --name nightly-health
```

```text
✓ Started fleet nightly-health (<FLEET_ID>). First turn <TURN_ID>: <varies>.
Talk to it with: agentsfleet fleet steer <FLEET_ID>
```

| Option | Effect | Default |
|---|---|---|
| `--name <NAME>` | Names the fleet. | A name based on the fleet identifier |
| `--model <REF>` | Selects an eligible `items[].ref` from `GET /v1/workspaces/{workspace_id}/models?purpose=runtime`. | The workspace default model |

With `--json`, creation prints `fleet_id` and `turn_id`.
Run `agentsfleet fleet steer @nightly-health` without a message to open an interactive chat with the fleet.

The private draft and Plugin commands are retired. [Retired Plugins](/fleets/library) describes the change.

### Fleets

| Command | Effect |
|---|---|
| `agentsfleet fleet create <MESSAGE>` | Creates the fleet and sends its first message. |
| `agentsfleet fleet show <FLEET_ID>` | Shows one fleet. |
| `agentsfleet fleet list` | Lists fleets in the active workspace. `--starting-after <CURSOR>` fetches the next page. With `--json`, it prints the server's page as returned. |
| `agentsfleet fleet status` | Shows every fleet in the active workspace, including how many approvals each one is waiting on. It takes no identifier — use `agentsfleet fleet show <FLEET_ID>` for one fleet. |
| `agentsfleet fleet archive <FLEET_ID>` | Cancels live work and keeps the fleet's history readable. Archiving is permanent. |
| `agentsfleet fleet delete <FLEET_ID>` | Deletes a fleet in any status, with its history and stored data. It cancels live work first. This cannot be undone. |
| `agentsfleet fleet logs [FLEET_ID]` | Shows recent activity. |
| `agentsfleet fleet turns <FLEET_ID>` | Lists the fleet's past messages and replies. |
| `agentsfleet fleet steer <FLEET_ID> [MESSAGE]` | Sends a message and streams the reply. Omit the message in a terminal to open chat. Use the fleet identifier or `@NAME`. |
| `agentsfleet fleet grants list --fleet <FLEET_ID>` | Lists integration grants for one fleet. |
| `agentsfleet fleet grants revoke --fleet <FLEET_ID> <GRANT_ID>` | Revokes one grant. Later access through that grant fails. |

Press **Ctrl+C** to stop local waiting and HTTP retries. An accepted message can keep running on the fleet.
Inspect `agentsfleet fleet turns <FLEET_ID>` before sending the message again.

Event polling reports permanent access or request errors immediately; its timeout also bounds an active read.

`agentsfleet fleet archive` and `agentsfleet fleet delete` have no dry-run option. Check the fleet identifier with `agentsfleet fleet show <FLEET_ID>` first.

### Approvals

| Command | Effect |
|---|---|
| `agentsfleet fleet approvals list` | Lists the gates waiting for a decision in the active workspace. |
| `agentsfleet fleet approvals list --fleet <FLEET_ID>` | Lists the waiting gates for one fleet. |
| `agentsfleet fleet approvals show <GATE_ID>` | Shows one gate, including the reach an approval grants. |
| `agentsfleet fleet approvals approve <GATE_ID>` | Approves the gate. The parked run continues. |
| `agentsfleet fleet approvals deny <GATE_ID>` | Denies the request. Work resumes without the requested access. |

If the list reaches its page limit with more results available, the command reports an incomplete list.
Narrow the request with `agentsfleet fleet approvals list --fleet <FLEET_ID>`.

A running fleet uses `request_access` when it needs a credential. A signed-in person can review the scope and approve or deny the request. Work resumes with the access the person granted.

See [Approvals](/fleets/approvals) for the scope of each decision and how to revoke a grant.

### Schedules

Every subcommand takes the fleet identifier. The four that act on one schedule
take its identifier after it.

| Command | Effect |
|---|---|
| `agentsfleet fleet schedule create <FLEET_ID> --cron <EXPRESSION> --message <TEXT>` | Creates a schedule that wakes a fleet on a cron expression. |
| `agentsfleet fleet schedule list <FLEET_ID>` | Lists the schedules a fleet holds. |
| `agentsfleet fleet schedule update <FLEET_ID> <SCHEDULE_ID>` | Changes an existing schedule. |
| `agentsfleet fleet schedule delete <FLEET_ID> <SCHEDULE_ID>` | Deletes one schedule. |
| `agentsfleet fleet schedule show <FLEET_ID> <SCHEDULE_ID>` | Shows one schedule and its state at the upstream scheduler. |
| `agentsfleet fleet schedule sync <FLEET_ID> <SCHEDULE_ID>` | Re-sends the schedule to the upstream scheduler. |

Run `agentsfleet fleet schedule sync <FLEET_ID> <SCHEDULE_ID>` when the saved schedule reports an unconfirmed registration.
A successful HTTP response can still carry a schedule whose synchronization failed; check its state and diagnostic message.

Each option is accepted by the subcommands named beside it.

| Option | Accepted by | Effect | Default | Unit or range |
|---|---|---|---|---|
| `--cron <EXPRESSION>` | `create`, `update` | Sets when the schedule fires. | Unset | Five-field cron expression |
| `--message <TEXT>` | `create`, `update` | Sets the message the fleet receives on each fire. | Unset | Text |
| `--timezone <TIMEZONE>` | `create`, `update` | Reads the cron expression in this zone. | `UTC` on `create` | Supported region name |
| `--status <STATE>` | `update` | Sets whether the schedule fires. | Unset | `active` or `paused` |
| `--workspace <WORKSPACE_ID>` | all six | Targets a workspace other than the active one. | Active workspace | Workspace identifier |

A fleet holds at most 32 schedules.

`agentsfleet fleet schedule list` prints `SCHEDULE_ID`, `SCHEDULE`, `STATUS`, `NEXT RUN`, `MESSAGE`, and `AGO`. `SCHEDULE` is the server's description of the expression with its zone, such as `At 9:00 AM (UTC)`.

```bash
agentsfleet fleet schedule list <FLEET_ID>
```

```text
SCHEDULE_ID   SCHEDULE            STATUS      NEXT RUN    MESSAGE     AGO
<varies>
```

`STATUS` reads `Scheduled`, `Paused`, `Activation pending`, or `Next run unavailable`. `NEXT RUN` is a Request for Comments (RFC) 3339 time only for a scheduled row, and `—` otherwise. The server computes both.

`create`, `update`, `show`, and `sync` print one line in the same terms.

```text
✓ created <SCHEDULE_ID>: At 9:00 AM (UTC) · Scheduled · Next run: <varies>
```

With `--json`, or when standard output is not a terminal, schedule commands print the server's JSON as returned. The exception is `delete`, which prints `{"deleted":true,"schedule_id":"<SCHEDULE_ID>"}` after the server confirms deletion. A schedule response missing a field the client reads fails with `SCHEDULE_RESPONSE_INVALID` and exit code `3`.

### Secrets and memory

| Command | Effect |
|---|---|
| `agentsfleet secrets create <NAME>` | Stores a JSON object in the workspace vault under a name that is free. A name already in use is reported as skipped, and nothing is written. |
| `agentsfleet secrets create <NAME> --provider <ID> --api-key <KEY> --model <MODEL>` | Stores a model-provider credential. `--provider` and `--model` are both checked against the model catalogue your server serves — run `agentsfleet models list` to list it. `--provider openai-compatible` adds a required `https` `--base-url`, makes `--api-key` optional, and accepts any `--model`. |
| `agentsfleet secrets update <NAME>` | Replaces a stored secret without releasing its name. It accepts the same data and provider options as `agentsfleet secrets create`. |
| `agentsfleet secrets show <NAME>` | Confirms that a secret exists without showing its value. |
| `agentsfleet secrets list` | Lists secret names, kinds, and creation times. Use `--json` for structured metadata. |
| `agentsfleet secrets delete <NAME>` | Deletes a secret. Fleets using the secret fail on their next use. |
| `agentsfleet fleet memory list --fleet <FLEET_ID>` | Lists memory entries newest first. |
| `agentsfleet fleet memory search <QUERY> --fleet <FLEET_ID>` | Searches memory keys and content. |

`agentsfleet secrets delete` has no dry-run option. The deleted secret value cannot be recovered.

### Model catalogue

| Command | Effect |
|---|---|
| `agentsfleet models list` | Lists regular models with names, providers, context windows, and input, cached-input, and output rates. |
| `agentsfleet models list --provider <ID>` | Lists one provider's models. |
| `agentsfleet models list --advanced` | Includes advanced models. Defaults to `false`. |

The table prints `MODEL`, `NAME`, `PROVIDER`, `CONTEXT`, `IN/MTOK`, `CACHED/MTOK`, and `OUT/MTOK`.
Context windows show exact token counts. Rates show exact dollars per million
tokens, including zero and fractions of a cent.

The client reads every catalogue page before printing. Use `--json` for each
model's full price schedule, context source, and verification time.

The dashboard's model picker reads the same catalogue. Model rates apply when
you use platform credentials. Your provider bills model usage when you supply
your own credentials.

If the catalogue is empty, ask an administrator to add models. During secret
creation, an empty or unavailable catalogue skips the client's provider check.
The server still validates the credential.

### Tenant settings

| Command | Effect |
|---|---|
| `agentsfleet models current` | Shows the active model provider. |
| `agentsfleet models use --secret <NAME>` | Selects a self-managed provider secret. |
| `agentsfleet models reset` | Returns the tenant to the platform provider. |
| `agentsfleet usage show` | Shows the account balance and recorded fleet-run charges. |

`--limit <COUNT>` reads 1 to 100 charge records per page, with a default of 10. Any value that is not a whole number in that range is refused with exit code `4`. Use the returned `next_cursor` as `<TOKEN>` in `--cursor <TOKEN>` to read the next page.

Charges for the same fleet event group within each page. Every returned charge contributes to the displayed totals, including a repeated charge and a category the client cannot label. Totals add exact nanodollar amounts, so no charge is rounded away.

## Errors

| Exit code | Meaning |
|---|---|
| `0` | The command succeeded. |
| `1` | Authentication, session, or unexpected failure. |
| `2` | Network failure or rate limit. |
| `3` | The API returned a server failure. |
| `4` | The invocation was rejected: a missing argument, a missing or unrecognized flag, a value that failed validation, or an unknown command. |
| `5` | Local configuration is missing or invalid. |
| `130` | You interrupted the command. |

Login reports network and API sign-in failures with exit code `1`.

A rejected invocation is answered before any request is sent. The form is always the same: what is wrong, then the command that puts it right. What is wrong may be an absent argument, a value that failed validation, or an unrecognized command.

```
$ agentsfleet fleet turns
✕ error: Missing required argument: fleet_id
  code          MISSING_ARGUMENT
  usage         agentsfleet fleet turns [options] <fleet_id>
  suggestion    run `agentsfleet fleet turns --help` for its arguments and flags
```

Under `--json` the same rejection is a parseable envelope on standard error, carrying a stable `code` you can switch on:

```json
{
  "error": {
    "code": "MISSING_ARGUMENT",
    "message": "Missing required argument: fleet_id"
  }
}
```

The codes are `MISSING_ARGUMENT`, `MISSING_OPTION_VALUE`, `MISSING_REQUIRED_OPTION`, `UNKNOWN_COMMAND`, `UNKNOWN_OPTION`, `INVALID_ARGUMENT`, and `EXCESS_ARGUMENTS`.

API failures include a stable error code and request identifier when the server supplies them. Use both values when reporting a problem.

A server failure displays the API's reader-facing message.

The [error registry](/api-reference/error-codes) lists the message each code carries.
