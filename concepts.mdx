## What it is

A fleet follows saved instructions to handle repeated work.

| Term | Meaning |
|---|---|
| Fleet | A saved task with instructions, tools, and spending limits. |
| Trigger | What starts work, such as a message, webhook, or schedule. |
| Event | One incoming delivery to the fleet. |
| Run | The fleet's work on one event. |
| Tool | An action the fleet may use, such as a request to another service. |
| Workspace | The home for fleets, secrets, connections, and member access. |

Your account owns its workspaces, billing, and model settings. The API calls the account a `tenant`.

## Why it exists

You set up repeated work once, then review results in the fleet's conversation and activity stream.
Workspace permissions control who can access the fleet.

## How it behaves

Describe a task in a private setup chat. Review the proposed instructions, access, and budget, then save the fleet.

A message or another declared trigger starts a run. The fleet uses its allowed tools and returns a result.
Memory can keep useful information for later runs.

Authorized workspace members can stop, resume, or kill a fleet. Deleting a killed fleet removes its records permanently.

## Limits

A fleet receives only its declared tools and secrets. [Network restrictions](/fleets/tools#how-it-behaves) depend on the tool and runner settings.
Budgets, account balance, and model limits can block new work.
