## What it is

An account has one credit balance shared by its workspaces. Each fleet run records model usage and time. The account that owns the fleet's workspace pays these charges.

## Why it exists

The balance lets you track and limit total account spending. Open **Usage** from the account menu or use the **Credits** link in the desktop sidebar.

## How it behaves

### How a run is charged

The server checks the account balance before assigning a run and checks it again during the run. It records model requests and runtime as separate charge lines.

When you use the platform model, agentsfleet charges for model usage and runtime. When you use your own provider key, the provider bills its tokens and agentsfleet charges for runtime.

Stopping a run ends its remaining work. Usage it already recorded is still charged.

### Review your spending

Choose a period and fleet in **Usage**. **By fleet** groups costs across your workspaces, and **Daily spend** shows daily totals. Charges retain the fleet name recorded at the time.

Read the current balance and usage from the terminal.

```bash
agentsfleet usage show
```

### Read charges through the API

| Request | Result |
|---|---|
| `GET /v1/tenants/me/billing` | The account balance |
| `GET /v1/tenants/me/billing/reports/current` | Totals, groups by fleet, and daily amounts |
| `GET /v1/tenants/me/billing/charges` | Individual recorded charges, newest first |

These requests need `billing:read`. The report accepts `period`, `fleet_id`, `activity_type`, and `through_at`. Use `runtime` if you set `activity_type`.

Periods use Coordinated Universal Time (UTC). `through_at` is an inclusive cutoff. Amounts are integer nanodollar strings, with 1,000,000,000 nanodollars per dollar.

## Limits

One balance covers all fleets in the account. Parallel runs can spend more before the next balance check, and a charge can take the account below zero.

New work is refused when the balance falls below the required floor. Credit added later first repays outstanding charges.
