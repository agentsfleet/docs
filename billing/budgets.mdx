## What it is

A fleet budget limits how much one fleet can spend. The fleet author sets the budget in `budget` under `config["x-agentsfleet"]` in the fleet's Definition.

```json
{
  "budget": {
    "daily_nanos": "5000000000",
    "monthly_nanos": "29000000000"
  }
}
```

Each limit is a decimal string of whole nanodollars. One dollar is `"1000000000"`, so the example allows 5 dollars a day and 29 dollars a month.

`daily_nanos` is required. `monthly_nanos` is optional; leave it out for no monthly limit.

## Why it exists

Every workspace under one tenant shares the same credit balance. A fleet budget stops one fleet from draining that shared balance.

The dashboard header shows what is left of that balance on every page, as a **Credits** chip beside the workspace switcher. It appears on screens at least 640px wide. Select the chip to open **Settings → Billing**, which holds the live figure and the charge history.

The fleet owns its budget. Applying a reviewed setup change replaces the limits, and deleting the fleet removes them.

## How it behaves

The daily limit covers a rolling 24-hour window. The monthly limit covers one Coordinated Universal Time (UTC) calendar month.

`agentsfleet` checks the limits before a run and while the run continues. A reached limit blocks new work and stops an active run at its next billing check.

A blocked event does not retry. Raise the limit in an improvement chat, apply the change, and send a new event.

The fleet, memory, and activity stream survive a budget stop. A stopped run has no final result.

### What a budget counts

A budget counts only the fleet's own runs. The setup chat that wrote or changed the fleet is charged to the workspace owner's balance, not to the fleet's budget.

While billing is available, a limit is checked before each run and at each renewal while it runs. A run already in progress can pass its limit by up to one renewal of usage before it stops.

If billing cannot answer, work continues and can exceed that bound. The full charge is settled later.

### How charges are counted

`agentsfleet` charges each provider request on its own line. A fleet run or setup chat also adds one run-time line for each stretch of time it ran. The charge history at `GET /v1/tenants/me/billing/charges` returns one row per line.

Each request is priced at the rate in effect when it was made, and at the tier its whole prompt falls in. Cached reads, cache writes, and output each use their own rate.

Each token category on a line is rounded up to a whole nanodollar on its own. A line can cost at most one nanodollar more per category than the exact amount, and never less.

Under a self-managed provider key, your provider bills the tokens and `agentsfleet` charges run time only.

Charges recorded during a billing outage settle once billing answers again.

Settlement charges the full amount and can take your balance below zero. New credit repays that debt before any remainder becomes spendable.

## Limits

| Field | Default | Unit | Valid range |
|---|---|---|---|
| `daily_nanos` | None; required | Nanodollars per rolling 24 hours | `"1"` through `"1000000000000"`, which is `$1,000` |
| `monthly_nanos` | None | Nanodollars per UTC month | `"1"` through `"10000000000000"`, which is `$10,000` |

Zero, signs, decimal points, exponents, and numbers outside the range are refused. A JSON number in place of the string is refused too.

An invalid budget blocks review and Save with `UZ-REQ-001`. A stored budget that cannot be read blocks the next run.

`UZ-RUN-015` marks a budget stop during a run.
The event's recorded failure class is `budget_breach`.
