## What it is

A fleet budget limits how much one fleet can spend. The fleet author sets the budget in `budget` under `config["x-agentsfleet"]` in the fleet's Definition.

```json
{
  "budget": {
    "daily_nanos": "5000000000",
    "monthly_nanos": "29000000000"
  }
}
```

Each limit is a decimal string of whole nanodollars. One dollar is `"1000000000"`, so the example allows 5 dollars a day and 29 dollars a month.

`daily_nanos` is required. `monthly_nanos` is optional; leave it out for no monthly limit.

## Why it exists

Every workspace in one account shares the same credit balance. A fleet budget stops one fleet from draining that shared balance.

Open the account menu to see your available balance and choose **Usage** for recorded charges.
The expanded desktop sidebar also shows a **Credits** link to Usage.

The fleet owns its budget. Applying a reviewed setup change replaces the limits, and deleting the fleet removes them.

## How it behaves

The daily limit covers a rolling 24-hour window. The monthly limit covers one Coordinated Universal Time (UTC) calendar month.

`agentsfleet` checks the limits before a run and while the run continues. A reached limit blocks new work and stops an active run at its next billing check.

A blocked event does not retry. Raise the limit in an improvement chat, apply the change, and send a new event.

The fleet, memory, and activity stream survive a budget stop. A stopped run has no final result.

### What a budget counts

A budget counts only the fleet's own runs. The setup chat that wrote or changed the fleet is charged to the workspace owner's balance, not to the fleet's budget.

While billing is available, a limit is checked before each run and at each renewal while it runs. A run already in progress can pass its limit by up to one renewal of usage before it stops.

If billing cannot answer, work continues and can exceed that bound. The full charge is settled later.

### Review your spending

Open **Usage** in the account menu to see confirmed charges across your account's workspaces.
These are called **settled charges**.

Choose a named month, such as **November 2026**, or **Last 7 days**, then filter by fleet.
**All Fleets** includes setup usage and saved-fleet usage; individual fleets follow it in the dropdown.

The dashboard displays activity timestamps and report ranges in your browser's timezone.

The totals cover all matching activity in the selected period, including activity on later pages.
**By fleet** groups settled charges by fleet and shows its recorded models.
Charge-detail controls are paused while their design is being prepared.

**Daily spend** shows complete daily totals from the report, including days with no settled charges.
The server supplies each complete bucket; the browser formats displayed dates and times.

**Setup chat** hides private draft titles and messages.

Input tokens are pieces of text the model reads; output tokens are pieces it writes.
The report retains recorded model identities and exact charges.
When a model name is unavailable, Billing shows its recorded identifier.

Each report includes charges confirmed by the time it was opened.
Pending usage stays outside its totals; newer reports can include charges confirmed later.
Missing usage information does not mean that usage was free.

Changing a filter starts a new report.

If loading fails, use **Retry report**.
A loading error is shown as an error, rather than as zero spending.

Usage has no Add credit action while its design is being prepared.

### Read charges through the API

`GET /v1/tenants/me/billing/reports/current` returns the report.
`GET /v1/tenants/me/billing/activities/{activity_id}/charges` returns one activity's individual charges.
Both require `billing:read` and use your signed-in account.

Each API activity groups charges from one fleet run or private setup attempt.
Activity and charge pagination retain the captured report time, so totals stay consistent.

Some older charges combine model use and run time in one amount.
The API keeps that recorded amount because separate historical prices are unavailable.

For activity charges, include `activity_type=runtime` for a fleet run or `activity_type=setup` for a setup attempt.
To match an existing report, keep its period, fleet and model filters, and `through_at` cutoff.
Use `starting_after` to read later pages without changing those values.

`agentsfleet` records each provider request and each billed stretch of runtime separately.
`GET /v1/tenants/me/billing/charges` returns those individual records.

Each request is priced at the rate in effect when it was made, and at the tier its whole prompt falls in. Cached reads, cache writes, and output each use their own rate.

Each token category on a line is rounded up to a whole nanodollar on its own. A line can cost at most one nanodollar more per category than the exact amount, and never less.

Under a self-managed provider key, your provider bills the tokens and `agentsfleet` charges run time only.

Charges recorded during a billing outage settle once billing answers again.

Settlement charges the full amount and can take your balance below zero. New credit repays that debt before any remainder becomes spendable.

## Limits

| Field | Default | Unit | Valid range |
|---|---|---|---|
| `daily_nanos` | None; required | Nanodollars per rolling 24 hours | `"1"` through `"1000000000000"`, which is `$1,000` |
| `monthly_nanos` | None | Nanodollars per UTC month | `"1"` through `"10000000000000"`, which is `$10,000` |

Zero, signs, decimal points, exponents, and numbers outside the range are refused. A JSON number in place of the string is refused too.

An invalid budget blocks review and Save with `UZ-REQ-001`. A stored budget that cannot be read blocks the next run.

`UZ-RUN-015` marks a budget stop during a run.
The event's recorded failure class is `budget_breach`.
