# Approve a waiting run

## What this does

Some fleets ask for access that a person has to grant. A run that asks parks at an approval gate until someone decides it.

`agentsfleet approvals` lists those gates, shows what one grants, and records the decision from your terminal.

## Before you begin

Install a fleet that opens gates. Two kinds reach the inbox, and they behave
differently:

| Kind | Raised by | Scope of a decision |
|------|-----------|---------------------|
| `repository_write` | `repository_access: write` in `TRIGGER.md` | One run. The next run opens its own gate. |
| `integration_grant` | a mintable credential in the bundle's `credentials:` list | Holds until somebody revokes the grant. |

A fleet can raise both. The `github-pr-reviewer` bundle does: it declares the
`github` credential and write access, so its first run asks twice.

Sign in and select the workspace that owns the fleet. A tenant API key needs `approval:read` to list gates and `approval:resolve` to decide them.

## Steps

1. List the gates waiting in the active workspace.

   ```bash
   agentsfleet approvals list
   ```

   ```text
   GATE      FLEET     KIND      STATUS    ACTION
   <varies>  <varies>  <varies>  <varies>  <varies>
   ```

   Add `--fleet <FLEET_ID>` to narrow the list to one fleet.

2. Read what the gate grants.

   `<GATE_ID>` comes from the `GATE` column.

   ```bash
   agentsfleet approvals show <GATE_ID>
   ```

   ```text
   <varies>
   ```

   The block names the fleet, the gate kind, its status, and the blast radius. The blast radius is one sentence naming what an approval reaches.

3. Decide the gate.

   ```bash
   agentsfleet approvals approve <GATE_ID>
   ```

   ```text
   <varies>
   ```

   Deny it instead when the reach is wider than the work needs.

   ```bash
   agentsfleet approvals deny <GATE_ID>
   ```

   ```text
   <varies>
   ```

## Verify it works

```bash
agentsfleet status
```

```text
Fleets
Name: <varies>
Status: active
Events: <varies>
Budget: <varies>
Waiting: 0
```

`Waiting` counts the gates the fleet is parked on. An approved run continues where it stopped, and `agentsfleet steer` returns its reply.

## Common problems

`UZ-APPROVAL-002` means the gate is no longer open. It timed out, or someone decided it in the dashboard. List the gates again.

`UZ-APPROVAL-006` means someone decided this gate first. Run `agentsfleet approvals show <GATE_ID>` to read the outcome and who recorded it.

`UZ-REPAIR-010` means the run asked for repository write access with no approved gate behind it. The run continues read-only, so it can name a fix but cannot push one.

`UZ-REPAIR-011` means the fleet's repository binding changed after the gate was raised. The fleet raises a new gate showing the current reach.

## Remove or undo

A gate is decided once, and neither answer can be changed on the gate itself. Denying one ends that run without the access it asked for. What an approval created is a separate object, and an integration grant can be revoked.

What a decision covers depends on the kind, and the difference matters most in
the direction people assume it does not.

A `repository_write` decision covers one run: the next run opens its own gate,
so approving today widens nothing tomorrow.

An `integration_grant` decision does not expire. Its blast radius says so —
`every credential this fleet mints for <service>, until a person revokes the grant` — so approving one is a standing permission, not a single answer. Revoke
it with `agentsfleet grant delete <GRANT_ID> --fleet <FLEET_ID>`; list what a
fleet holds with `agentsfleet grant list --fleet <FLEET_ID>`.

Removing `repository_access: write` from `TRIGGER.md` and pushing the bundle
with `agentsfleet fleet update` stops the per-run write gates. It does not stop
every gate. A fleet that declares mintable credentials still raises an
`integration_grant` gate the first time it needs them.

To stop being asked at all, a fleet has to declare neither write access nor a
mintable credential.

Run `agentsfleet approvals list --fleet <FLEET_ID>` to see which kind you are
actually being asked about — the `KIND` column names it.
