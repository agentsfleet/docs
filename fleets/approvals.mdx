## What this does

Review what a fleet wants to do before granting access. A run that needs
approval waits until someone approves or denies its request.

Open the fleet conversation to decide a request. Summary shows the proposed action and affected resources; choose **Approve** or **Deny** there.

Read the scope on the access card before deciding.

A confirmed decision appears beside the action. If the response is uncertain, choose **Check status** before deciding again.

Use `agentsfleet fleet approvals` to inspect requests and decide them from your terminal.

## Before you begin

A running fleet asks for a workspace secret or connected provider with `request_access`. Its request names the service and, for GitHub, the repositories and access level.

Sign in to the workspace that owns the fleet. Deciding a request needs `approval:resolve` and a signed-in person's session. A tenant API key with `approval:read` can list the requests.

## Steps

1. List the gates waiting in the active workspace.

   ```bash
   agentsfleet fleet approvals list
   ```

   ```text
   GATE      FLEET     KIND      STATUS    ACTION
   <varies>  <varies>  <varies>  <varies>  <varies>
   ```

   Add `--fleet <FLEET_ID>` to narrow the list to one fleet.

2. Read what the gate grants.

   `<GATE_ID>` comes from the `GATE` column.

   ```bash
   agentsfleet fleet approvals show <GATE_ID>
   ```

   ```text
   <varies>
   ```

   Check the fleet, request kind, and status. The `blast_radius` describes
   exactly which actions your approval permits.

3. Decide the gate.

   ```bash
   agentsfleet fleet approvals approve <GATE_ID>
   ```

   ```text
   <varies>
   ```

   Deny the request if it asks for more access than the task needs.

   ```bash
   agentsfleet fleet approvals deny <GATE_ID>
   ```

   ```text
   <varies>
   ```

## Verify it works

```bash
agentsfleet fleet status
```

```text
Fleets
Name: <varies>
Status: active
Events: <varies>
Budget: <varies>
Waiting: 0
```

`Waiting` counts requests that need your decision. Approving a waiting run lets
it continue, and `agentsfleet fleet steer` returns its reply.

## Common problems

`UZ-APPROVAL-002` means the gate is no longer open. It timed out, or someone decided it in the dashboard. List the gates again.

`UZ-APPROVAL-006` means someone decided this gate first. Run `agentsfleet fleet approvals show <GATE_ID>` to read the outcome and who recorded it.

`UZ-GRANT-001` means the fleet has no approved grant for the service.
No credential is issued, and the run makes no provider call. Check with
`agentsfleet fleet grants list --fleet <FLEET_ID>`.

`UZ-REPAIR-010` and `UZ-REPAIR-011` are retired and no longer returned. Both described a per-event repository-write gate that is no longer raised. A run that cannot write now fails with `UZ-GRANT-001` instead.

## Remove or undo

A request can be decided once. Denying resumes the work without the requested access. You can revoke an approved integration grant.

To revoke a grant, copy `<GRANT_ID>` from `agentsfleet fleet grants list --fleet <FLEET_ID>`.
Then run `agentsfleet fleet grants revoke <GRANT_ID> --fleet <FLEET_ID>`.

To change the approved repository scope, revoke the existing grant. Ask the fleet to request the new scope, and decide its next access card.

The next run and token mint use the updated approval. A credential already issued to a live run remains with that run.
