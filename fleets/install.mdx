# Install a fleet

## What this does

This creates a fleet from one published Library revision. You review the revision's setup under your fleet name, then save it.

Saving pins the fleet to that revision. A later revision of the same entry never changes the fleet until you apply it yourself.

## Before you begin

Sign in and select a workspace. Save every secret the entry needs; the review lists them.

`<MODEL_REF>` names an authoring model the workspace owner enabled. [Author a fleet](/fleets/authoring) shows where it comes from. A Library draft starts without a chat message, so no authoring model call runs.

## Steps

1. Browse the workspace gallery.

   ```bash
   agentsfleet library
   ```

   ```text
   NAME        LIBRARY     TIER        REVISION    AGO
   <varies>
   Start from a revision: agentsfleet chat --library <library_id> --revision <revision_id>
   ```

   The gallery holds both tiers. `TIER` reads `platform` for an entry every workspace sees and `tenant` for one this workspace owns. `REVISION` is the entry's latest revision.

2. Open a private draft from that revision and review it under your fleet name.

   `<LIBRARY_ID>` and `<REVISION_ID>` come from the gallery. `<NAME>` is the fleet name you choose.

   ```bash
   agentsfleet chat --library <LIBRARY_ID> --revision <REVISION_ID> --model <MODEL_REF> --no-input --review --name <NAME>
   ```

   ```text
   ✓ Draft <DRAFT_ID> created
   Instance: <NAME>
   Runtime model: <varies>
   <varies>
   Review digest: <DIGEST>
   ```

   The review shows the full setup, the secrets, tools, and network hosts it needs, and a readiness line for each.

3. Save the draft with the digest you reviewed.

   ```bash
   agentsfleet chat <DRAFT_ID> --no-input --save --name <NAME> --review-digest <DIGEST>
   ```

   ```text
   <varies>
   ✓ Fleet <NAME>: active
   ```

   Add `--run-now <MESSAGE>` to send the fleet one message once it is active.

4. Read the fleet's webhook URLs, if its setup declares a webhook trigger.

   `<FLEET_ID>` comes from `agentsfleet list`.

   ```bash
   agentsfleet --json fleet show <FLEET_ID>
   ```

   ```text
   <varies>
   ```

   Each `webhook_urls` entry pairs a `source` with its `url`. For GitHub, open **Repository settings → Webhooks → Add webhook**. Use the matching workspace webhook secret.

In the dashboard, open **Fleet library**, choose an entry, and choose **Start chat from this revision**.

## Verify it works

```bash
agentsfleet status
```

```text
Fleets
Name: <NAME>
Status: active
Events: <varies>
Budget: <varies>
Waiting: 0
```

`Waiting` counts the approvals this fleet is parked on. A count above zero also
prints the command that lists them.

## Common problems

A Save that prints `installing` and exits with code `1` is waiting on a setup check. The lines after it name each check, such as a missing secret or a pending integration grant, and its next step.

Fix each check, then run `agentsfleet resume <FLEET_ID>` to check again. The fleet keeps its identifier while it waits.

`UZ-AUTHOR-006` means the setup or its access changed after your review. Review again and save with the new digest.

`UZ-AGT-006` means the fleet name already exists. Review again under a different `--name`.

To reuse the taken name instead, run `agentsfleet kill <FLEET_ID>` and then
`agentsfleet delete <FLEET_ID>`. Deletion releases the name.

<Warning>
  `agentsfleet delete` is irreversible. It takes the Fleet's events, sessions,
  schedules, integration grants, connector channels, and memory with it — a
  name is the only thing you get back. When you only need the name free, prefer
  a different `--name` and leave the existing Fleet in place.
</Warning>

A Save whose reply was lost, or that stays `installing`, prints a recovery line with `--operation-id` and `--candidate-id`. Repeat the same command with both flags to resume that Save without creating a second fleet.

## Remove or undo

Deleting a fleet removes its events, telemetry, sessions, grants, keys, and memory. This loss cannot be undone.

`<FLEET_ID>` comes from `agentsfleet list`. Kill the fleet before deleting it.

```bash
agentsfleet kill <FLEET_ID>
```

```text
✓ <varies> killed.
```

```bash
agentsfleet delete <FLEET_ID>
```

```text
✓ <varies> deleted.
```
