## What it is

The dashboard and command-line interface (CLI) call reusable fleet setups **Plugins**. The API keeps the Fleet library names.

A library entry is reusable fleet setup. It holds one or more immutable revisions, and each revision is a reviewed Definition with its required secrets, tools, and network hosts.

The platform library is visible to every workspace. Your account's entries are private to that account and can be reused across its workspaces.

## Why it exists

The library lets a workspace reuse a setup that someone already reviewed.

## How it behaves

Entries come only from reviewed chat drafts. Saving a fleet never publishes it, and publishing never creates a fleet.

The dashboard lists your account’s published setups under **Your plugins**. Private setups from other accounts never appear. The terminal gallery also lists available platform setups.

Choose **Create in chat** to write a new setup. Start a fleet setup chat, then save or publish your setup.

Each new fleet starts from one pinned revision. A later revision of the entry does not change fleets saved from an earlier one. Plugins do not compose capabilities into an existing fleet.

### Start from a revision link

Publish a reviewed pull-request setup to reuse its instructions as an editable starting point.

1. Open **Plugins** and choose the menu beside a setup.
2. Read **Inspect setup**, or use **Choose a saved version** to inspect an earlier revision. Choose **Use for new fleet**.
3. Copy the resulting browser address to start another setup from that same revision.

The recipient needs access to the workspace and Library entry. A link grants no additional access and includes no private setup conversation.

Each person starts a private setup chat. Describe your changes, review the proposed instructions and access, then choose **Save fleet**.

### Start from the terminal

The terminal calls a library entry a plugin. `agentsfleet plugins` lists the gallery this workspace can use, which holds both tiers. `TIER` reads `platform` for an entry every workspace sees and `tenant` for one your account owns.

```bash
agentsfleet plugins
```

```text
NAME        PLUGIN      TIER        REVISION    AGO
<varies>
Start from a revision: agentsfleet chat --plugin <plugin_id> --revision <revision_id>
```

`REVISION` is the entry's latest revision. [Install a fleet](/fleets/install) shows how to save a fleet from it.

A page with no entries reads `No published plugins on this page.` and shows how to publish one.

## Publish an entry for your account

You publish from a reviewed draft. Publishing does not close the draft, so you can keep editing it.

In the dashboard, open **Publish plugin** and enter a **Plugin name**. Choose **Publish new entry**, or **Publish next revision** for the selected owned entry. **Edit setup** opens a private chat pinned to that plugin revision.

If an unpublished edit was reloaded, choose **Update an existing plugin** and select its destination before publishing the next revision. Selecting a destination does not publish. Existing fleets keep their pinned setup.

In the terminal, publish a reviewed draft with a label. `<LABEL>` is the display name, 1 to 100 characters. `<DRAFT_ID>` and `<DIGEST>` come from the draft's review.

```bash
agentsfleet chat <DRAFT_ID> --no-input --publish <LABEL> --review-digest <DIGEST>
```

```text
<varies>
✓ Published plugin revision <REVISION_ID>
```

Inside an interactive chat, `/publish <LABEL>` does the same after a `/review`.

To add a revision to an entry your account owns, add `--publish-to <PLUGIN_ID> --plugin-etag <ETAG>`. `<ETAG>` is the entry's `etag` field from `agentsfleet --json plugins list`. A stale tag is refused, so the revision always follows the version you inspected.

Publishing needs the `library:write` scope.

| Option | Effect | Default | Unit or range |
|---|---|---|---|
| `--publish <LABEL>` | Publishes the reviewed draft as a new entry. | None | Text, 1 to 100 characters |
| `--publish-to <PLUGIN_ID>` | Appends a revision to this owned entry instead. Needs `--publish` and `--plugin-etag`. | None | Plugin identifier |
| `--plugin-etag <ETAG>` | The entry tag you inspected. | None | Entity tag |
| `--review-digest <DIGEST>` | The digest of the review you inspected. | None; required | Digest text |

## List and remove your account's entries

`agentsfleet plugins list` lists only the entries your account owns. It never shows a platform entry.

```bash
agentsfleet plugins list
```

```text
NAME        PLUGIN      TIER        REVISION    AGO
<varies>
```

`agentsfleet plugins delete` takes one identifier from the `PLUGIN` column.

<Warning>
  Removal is permanent. The entry and its revision history leave the gallery, and nothing restores them.
</Warning>

```bash
agentsfleet plugins delete <PLUGIN_ID>
```

```text
✓ <varies> is no longer one of this workspace's plugins. Fleets already installed from it keep running.
Publish reviewed chat setup with: agentsfleet chat --help
```

A draft started from the entry, or published to it, stays. The draft loses its link to the entry and keeps its own content.

You can remove only an entry your account owns. A platform entry, another account's entry, or an entry already removed answers `404` with `UZ-AUTHOR-001`. All three answer the same way, so the reply never tells you whether an entry exists elsewhere.

Removal needs the `library:write` scope.

The dashboard lists your account’s entries under **Plugins**. Open a setup’s menu for **Edit setup**, **Use for new fleet**, or **Choose a saved version**.

## Platform entries

Platform entries come from a reviewed draft too. An operator whose session carries the `platform-library:write` scope stages the draft, and the entry starts hidden.

Use `agentsfleet platform fleet-library` in the terminal. Its commands list, inspect, stage, update, publish, unpublish and delete platform entries. Platform administration has no dashboard page.

Publishing and metadata edits require the entry’s current `--etag`. If another operator writes first, reread the entry and review the newer values before retrying. **Unpublish** hides a published entry; only an unpublished entry can be deleted.

Existing fleets keep their pinned setup revision.

## Limits

A Definition's description allows 32,768 characters, and so do its instructions. The first instructions a chat model writes allow 12,288 characters. The whole Definition allows 448 KiB of JSON.

A Definition declares at most 128 tools, 64 secrets, and 64 network hosts. A tool name allows 128 characters, a secret name 128, and a network host 255.

Library lists return 100 entries per page at most. Use `--starting-after <CURSOR>` with the cursor the previous page prints.

Removing a fleet does not remove its library entry. Remove the entry itself with `agentsfleet plugins delete <PLUGIN_ID>`.
